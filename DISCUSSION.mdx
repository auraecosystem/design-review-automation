## Summary

In **Copilot cloud agent**, as soon as the agent views an image file (PNG/JPG) with its `view` tool, the next model request fails and the session stops with:

```
Execution failed: CAPIError: 400 Error while downloading file. Upstream status code: 404.
```

- Fails on **GPT models** (gpt-5.4, gpt-5.3-codex).
- The same flow on **claude-sonnet-5** views the same image and completes normally.
- The same images view fine in the **local Copilot CLI** (1.0.83) with gpt-5.4 and gpt-5.3-codex.

## Environment

- Account: HaiDuc0147 (Copilot Pro)
- Repository: HaiDuc0147/copilot-image-repro (private — happy to grant access)
- Product: Copilot cloud agent, started by assigning an issue to Copilot or from the Agents tab
- Model chosen explicitly in the UI: GPT-5.4 fails, Claude Sonnet succeeds

## Steps to reproduce (minimal, no MCP servers)

1. Repository containing a small PNG, e.g. `images/small.png` (2 KB).
2. Create an issue: "Look at images/small.png and write a one-paragraph description of it to NOTES.md."
3. Assign to Copilot with model **GPT-5.4**.
4. The agent calls `view images/small.png` (log: `view success=true`); the next request fails with the CAPIError above.
5. Repeat with model **Claude Sonnet** — the agent views the image and completes.

## What the logs show

- The `view` tool succeeds. The failure is on the *following* request, before any `assistant.usage` line for that turn — it looks like CAPI rejects the request while resolving the uploaded image attachment for the OpenAI route.
- The runner has `GITHUB_UPLOADS_URL=https://uploads.github.com/user-attachments/assets` and `GITHUB_DOWNLOADS_URL=https://api.github.com/internal/user-attachments/assets`; both hosts are on the firewall allowlist.
- The image source doesn't matter (file in the repo, `/tmp`, or downloaded with curl) — any viewed image fails on GPT.
- In one run the error was delayed: image viewed at turn 6, error at turn 30 after `session.idle`.
